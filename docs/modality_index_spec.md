# 図表・グラフ・数式の意味的つながりを索引に持つ 仕様

作成日: 2026-08-03 / 状態: **未実装**（`predictions_8b_chunk_k100_rrf.jsonl` の走行中のため
コードは一切変更していない）

「論文ごとでも論文をまたいでもいいから、図表・グラフ・数式の意味的なつながりを
事前に索引として持ち、検索で使う」案の検討結果と実装仕様。

---

## 1. 先に測った: どのモダリティに伸びしろがあるか

検証55件の `primary_evidence_type` 別に、候補列の論文単位 recall を出した
（土台 `predictions_8b_chunk_cand50.jsonl` / RRF統合は本仕様と同じ設定のオフライン結果）。

| primary_evidence_type | n | 展開なし cr@20 | 展開なし ecr@20 | **RRF統合 cr@20** | **RRF統合 ecr@20** |
|---|---|---|---|---|---|
| table | 17 | 0.941 | 0.941 | 0.926 | 0.926 |
| figure | 15 | 0.767 | 0.867 | **0.900** | **0.956** |
| text_span | 9 | 0.611 | 0.787 | 0.833 | 0.944 |
| citation_context | 7 | 0.929 | 1.000 | 0.929 | 1.000 |
| **equation_algorithm** | **7** | 0.560 | 0.667 | **0.726** | **0.762** |

**論文単位では、図と表はすでに解けている。** figure は RRF 統合で 0.767 → 0.900
（ecr 0.956）まで上がり、table は元から 0.926〜0.941。論文単位で残っている弱点は数式
（cr@20 0.726 / ecr@20 0.762）で、5モダリティ中ただ一つ 0.8 を切っている。

### 1.1 ただし「図を読まないと答えられないクエリ」は別の壊れ方をしている

論文単位の recall だけ見ていると見落とす。gold の evidence を `source_type` 別に、
**その根拠を当てられたか**と**その論文は提出できていたか**の2軸で数えると:

| source_type | gold本数 | evidence 一致 | （その論文は提出済み） |
|---|---|---|---|
| table | 64 | 0.406 | 0.719 |
| text_span | 54 | 0.056 | 0.519 |
| **figure** | **18** | **0.111** | **0.833** |
| equation_algorithm | 7 | 0.000 | 0.714 |
| citation_context | 6 | 0.000 | 1.000 |

（`predictions_8b_chunk_k100_expand_fused.jsonl`、`evaluate.py` の `coarse_evidence_key` で照合）

**図は論文の 83.3% を提出できているのに、正しい図を当てられたのは 11.1%**。7.5倍の落差で、
5モダリティ中もっとも大きい。提出した evidence の内訳を見るとさらにはっきりする:

| | table | text_span | figure | equation | title_abstract |
|---|---|---|---|---|---|
| gold（149件） | 64 | 54 | **18** | 7 | — |
| 提出（92件） | 43 | 36 | **6** | 2 | 5 |

**図はそもそも出力に到達していない。** 本番のクエリで図の読み取りが鍵になるものが来たとき、
論文だけ当てて根拠を外す形で落ちる。

### 1.2 だが原因は埋め込みより手前にある

`ReadingAgent` が LLM に見せるのは **1論文につき `chunks_per_paper: 2` チャンクだけ**
（`_candidate_papers()`）。1論文のチャンク数は実測（12論文）で
text_span 66 / table 11 / figure 9 / equation 9 の**約95件**なので、
**図が上位2件に入る確率は構造的に低い**。しかも `evidence` は LLM が引用した chunk_id
からしか作られないため、見せていない図は絶対に根拠にならない。

つまり「図を意味的に結び直す索引」を作っても、その図が LLM に渡らなければ効かない。
**先に潰すべきは「どのチャンクを渡すか」で、これは検索側（＝我々）の責任範囲**にある。
画像埋め込みはその後の話。

## 2. 採る案: 数式シンボル結合を **ランキングB の4つ目のソース**にする

`reading_expand_rrf/rrf.yaml` のランキングB（論文→論文の関連度）に、
`specter2` / `bib_coupling` / `bm25_mlt` と並ぶ4つ目として足す。
**質問→図表の検索索引を新設するのではなく、論文→論文の「近さ」の一種として持つ**のが要点。
同じ手法系譜の論文は同じ数式形を使い回すので、書誌結合と同じ形の signal になる。

### 2.1 実装（`bib_coupling` と同じ構造）

`@register("expander", "equation_coupling")` を `retrieve/paper_expander.py` に足す。

- コーパス1走査で `equation_algorithm` チャンクだけを拾い、LaTeX から記号語彙を抽出する。
  正規表現は実測で使ったもの: `\\[A-Za-z]{2,}|[A-Za-z]\s*_\s*\{[^{}]{1,12}\}`
  （`\mathcal` などのコマンドと `x_{t}` のような添字つきシンボル）。空白は除去する
  （MinerU の LaTeX は `\bar { L } _ { i }` のように字間が割れる）。
- `{paper_id -> 記号集合}` と転置索引を pickle にキャッシュ（`refs.pkl` と同じ作法）。
- 近さは **IDF 重み付きコサイン**。生の Jaccard ではだめ（下記2.2）。
- params: `min_df`（既定2、OCR ノイズを切る）、`max_df_ratio`（既定0.1、`\frac` のような
  汎用コマンドを切る）、`neighbors`、`anchors`。GPU 不要。

パス導出は `config.py` の `compose_config()` に分岐を1つ足すだけ:
`cache_path = {index_dir}/{process}/equation_coupling/symbols.pkl`、
`chunks = resolved_paths["chunks"]`。

### 2.2 効くか: 実測プローブ（TCM クラスタ、標本304論文）

anchor = `iclr2025_03463`(TCM)、ピア3本 = `iclr2025_00615` / `iclr2025_03031` /
`icml2025_01371`(IMM)。

| 指標 | ピア3本 | 無作為300本 |
|---|---|---|
| 生の Jaccard | 0.517 / 0.465 / 0.452 | 中央値 0.241・最大 0.449 |
| **IDF重みコサイン** | **0.256 / 0.169 / 0.118** | 中央値 0.045・95%点 0.141・最大 0.192 |

**IDF 重みが必須。** 生の Jaccard ではピア最下位(0.452)が無作為の最大(0.449)とほぼ同じで
分離しない——`\frac` `\left` `\mathcal` のような全論文に出るコマンドが支配するため。

**ただし書誌結合ほどきれいには分離しない。** 書誌結合はピア 0.19〜0.24 に対し無作為が
中央値 0.000・最大 0.054 で完全分離だったが、数式は**ピア最下位(IMM, 0.118)より上に来る
無作為論文が 10.3%** ある。27,487論文に外挿すると約2,800本が IMM を上回る計算で、
**単独ソースとしては IMM を近傍50本に入れられない**。

したがって位置づけは「単独では使えないが、RRF の1票としてなら効きうる」。
最強のピア(0.256)は無作為300本の最大(0.192)を上回るので、少なくとも一部のピアは
上位に置ける。RRF は1ソースがノイジーでも他が支えるので破綻はしない。

### 2.3 検証手順（15秒で回る）

索引キャッシュを1回作れば、あとは `scripts/replay_expansion.py` でソース構成を
差し替えるだけ。**4ソース目は足せば効くとは限らない**——実測でソースどうしは
干渉する（3ソースは2ソースより cr@20 +2.0pt だったが、組み合わせによっては下がる）。

```
uv run python scripts/replay_expansion.py \
  --paths configs/paths/default.yaml --process configs/process_style/mineru.yaml \
  --search configs/search_style/bm25_qwen3_8b_rerank_qwen3_8b/chunk_attrfilter.yaml \
  --agent configs/agent_style/reading_expand_rrf/rrf.yaml \
  --pred predictions_8b_chunk_cand50.jsonl --output /tmp/eq.jsonl \
  --set 'sources=[{name: specter2, index_name: faiss_specter2_abstract},
                  {name: bib_coupling, min_shared: 2},
                  {name: bm25_mlt},
                  {name: equation_coupling}]'
```

判定は `primary_evidence_type == equation_algorithm` の7件の cr@20 / ecr@20 で見る
（現状 0.726 / 0.762）。全体マクロは7件ぶんしか動かないので、そこだけ見ても差が埋もれる。

**採否ライン**: 数式7件の ecr@20 が上がり、かつ全体の ecr@20 が 0.926 から下がらないこと。
片方でも満たさなければソースに入れない。

## 2.5 併せて採る案: LLM に渡すチャンクのモダリティ枠（安い順に3段）

1.1 で見たとおり、図の根拠が出ないのは索引ではなく**渡していない**ことが原因。
安い順に3つあり、**上から順に試して効かなくなった時点で止める**。

### 段1: `chunks_per_paper` を上げる（設定変更のみ、実装ゼロ）

`reading_expand_rrf/rrf.yaml` の `chunks_per_paper: 2` を 4 にする。LLM に渡るトークンは
`max_candidates(20) × chunks_per_paper × snippet_chars(1800)` で効くので、
20×2×1800 ≈ 7万字 → 14万字。`max_candidates` を 20 → 12 に落として総量を保つ案と
両方測る。**A/B は本走行が要る**（オフライン再生は候補列しか触れず、LLM 読解を再現できない）。

### 段2: モダリティ枠（`_candidate_papers()` を数行）

各論文の上位 `chunks_per_paper` 件を**スコア順にそのまま取る**のをやめ、
**chunk_type 別に枠を確保する**。質問が図表を要求しているとき
（`answer_types` に table がある / 質問文に figure・table・plot・curve 等が出る）、
1論文につき最低1枠を figure または table のチャンクに割り当てる。
枠に入る候補が無ければ従来どおりスコア順で埋める（fail-open）。

`_candidate_papers()` は既に論文ごとに `results` をスコア降順で持っているので、
そこから type 別に取り分けるだけ。索引も再構築も不要。属性フィルタと同じ
「取ってから選び直す」型の打ち手で、どの search_style にも同じように効く。

### 段3: 図チャンクのテキストを VLM キャプションで厚くする

`preprocess/figure_vlm.py` の `FigureVLMChunker`（Qwen2-VL-7B-Instruct）が既にあり、
`configs/process_style/figure_vlm.yaml` も用意されている。図の中身を文章にしてから
既存のテキスト索引に載せるので、**画像埋め込み索引を新設せずに**
「キャプションに書いていない図の中身」を検索可能にできる。
25万件の図に VLM を回すコストはかかるが、隔離 venv は不要で、
出来上がるのは既存の `faiss_qwen3` / `bm25s` にそのまま入るテキストチャンク。

## 3. 保留にする案

### 3.1 表スキーマ結合（`table_coupling`）

`table` チャンクから列見出しとデータセット名を抜き、共有する (データセット, 指標) の組で
論文を繋ぐ。「同じベンチマーク表で比較している論文」= multi_paper のピア構造そのものなので
筋は良い。

**保留の理由**: table の cr@20 が既に 0.926 で、論文単位の伸びしろが約1件しかない。
数式（0.726）を先に潰すほうが期待値が高い。数式で手応えがあれば同じ構造で追加できる
（実装コストはほぼ同じ）。**未プローブ**なので、着手前に2.2と同じ分離度の測定を先にやること。

### 3.2 図の画像埋め込みグラフ

図を SigLIP / Qwen3-VL-Embedding-8B で埋め込み、論文をまたいだ図の近傍で論文を繋ぐ案。
`siglip_image` / `qwen3_vl_image` indexer は既にあるので索引は作れる。

**「まだやらない」であって「効かない」ではない。** 1.1 のとおり図の根拠特定は
0.111 と実際に壊れており、本番で図の読み取りが鍵になるクエリは落ちる。順番の問題として
後ろに置く:

1. **論文単位の識別には伸びしろが無い**。figure の cr@20 は RRF 統合後 0.900 / ecr@20 0.956。
   ランキングB のソースとして足す価値は薄い。
2. **根拠特定の側では、渡していないことが先に効いている**（1.2）。1論文95チャンクのうち
   2件しか LLM に見せていない状態で図の索引を足しても、その図は選ばれない。
   **段1・段2（2.5節）を先にやらないと、画像埋め込みの効果そのものが測れない。**
3. **コストが重い**。図チャンクは1論文あたり約9件（12論文の実測: text_span 790 /
   table 130 / figure 110 / equation 104）で、全体では約25万件。8B 系の埋め込みは
   隔離 venv `.venv-vl` が要るうえ、索引構築は数十時間規模。同じ目的なら段3の
   VLM キャプション（既存のテキスト索引に載る）のほうが先に試す価値がある。

**着手条件**: 段1〜段3をやったうえで、図の evidence 一致が 0.111 から十分に上がらない、
かつ「キャプションに書かれていない見た目の類似」で取り逃していると `--per-query` で
特定できたとき。そのときは `configs/search_style/bm25_qwen3_vl_8b_rerank_qwen3vl_8b.yaml`
が既にあるので、まず既存構成で55件を1本回して測る。

### 3.3 論文内の図表↔本文リンク

「Figure 3 shows …」という本文と `figure_id: 3` のチャンクを事前に結び、
どちらかがヒットしたらもう片方も引く案。**論文単位の識別には効かない**
（同じ論文のチャンクなので `to_gold_papers` が max を取った時点で同じ1本になる）。
効くのは evidence 側と、reranker に渡すプールの中身。担当範囲外。

## 4. まとめ

問題は2つに分かれる。**どの論文かを当てる**側と、**その中のどの図表かを当てる**側。

### 論文単位の識別（cr / ecr）

| 案 | 対象モダリティの現状 cr@20 | コスト | 判断 |
|---|---|---|---|
| 数式シンボル結合 | **0.726**（最弱） | 1走査+pickle、GPU不要 | **採る**（ただし分離度は書誌結合より弱い） |
| 表スキーマ結合 | 0.926 | 同上 | 保留（数式の結果を見てから） |
| 図の画像埋め込みグラフ | 0.900 | 25万件×8B、隔離venv、数十時間 | 伸びしろ無し、やらない |

図表は論文単位ではもう効いており、同じ発想を数式に向けたときだけ取り分がある。
しかも7件ぶんで、全体 cr@20 への寄与は最大 +3.5pt が上限。

### 根拠（どの図表か）の特定 — こちらのほうが壊れている

| 段 | 打ち手 | コスト | 判断 |
|---|---|---|---|
| 1 | `chunks_per_paper: 2 -> 4` | 設定変更のみ | **先にやる** |
| 2 | モダリティ枠（`_candidate_papers()` に type 別の枠） | 数行、索引不要 | 段1で足りなければ |
| 3 | 図チャンクの VLM キャプション（`figure_vlm.py` 既存） | 25万件×VLM、隔離venv不要 | 段2で足りなければ |
| 4 | 図の画像埋め込み索引 | 25万件×8B、隔離venv | 段3で足りなければ |

図の evidence 一致は 0.111（論文は 0.833 取れている）。**1論文95チャンクのうち2件しか
LLM に見せていない**のが先に効いているので、段1・段2を飛ばして段4に行っても効果が測れない。

評価指標は `evidence_f1` ではなく `source_type == figure` に絞った evidence 一致率で見る
（全体の `evidence_f1` は table と text_span に薄められて図の改善が埋もれる）。
